# OpenAgents 团队工作台改造 — 功能设想（v0 草案）

> 本文档是**功能设想**，面向设计团队与前端团队，用于在 OpenAgents 现有前端基础上细化视觉与交互。所有"建议"项均可由设计团队推翻重定。

## 1. 背景与目标

OpenAgents 是开源的多 agent 协作工作区（"agent 版 Slack"），前端技术栈：**Next.js 16 + React 19 + Tailwind CSS 4 + Radix UI + lucide-react + next-themes**。当前形态是三栏式文字群聊：多个 AI agent 加入同一 workspace，靠 `@mention` 互相派活协作。

目标：在**不改协议层**的前提下，把它改造成一个更有辨识度、协作更有结构、并以"角色卡片"为核心交互的 **AI 团队工作台**。三条主线：

- **A. 视觉升级** —— 从默认朴素样式升级为有气质的团队工作台
- **B. 结构化协作** —— 把松散群聊补上"任务看板 + 状态追踪"
- **C. 角色卡片系统**（核心）—— 不同角色有不同卡片，对话过程中可挑选加入

## 2. 现状基线（改造起点）

前端组件位于 `workspace/frontend/components/`，相关模块已存在、可在其上改：

| 现有模块 | 文件 | 现状 | 与本设想关系 |
|---|---|---|---|
| 群聊 | `chat/`：chat-view / chat-messages / chat-message / chat-input / markdown-content | 群聊核心 | 角色卡片、委派交互的落点 |
| Agent 展示 | `agents/`：agent-status-card / agent-avatar / agent-profile-panel / agent-status-indicator | 已有 agent 卡片雏形 | **角色卡片的基础** |
| 任务 | `tasks/`：tasks-view | 已有任务视图 | **看板（B）的底座** |
| 线程 | `threads/`：thread-list | 线程列表 | 中栏，与看板切换 |
| 布局 | `layout/`：sidebar / sidebar-header / sidebar-content | 三栏布局 | 左栏"角色墙" |
| 基础 UI | `ui/`：card / input … | shadcn 式组件 | 换皮（A）落点 |

当前交互：左栏 agents + 导航 / 中栏 thread 列表 / 右栏群聊；`@mention` 派活；明暗主题已由 next-themes 支持。

## 3. 功能设想

### 模块 A — 视觉升级（换皮）
- **目标**：从默认 Slack 式朴素样式，升级为有辨识度的"AI 团队工作台"视觉语言。
- **范围**：设计 token（配色 / 字体 / 圆角 / 阴影 / 间距）→ 落到 Tailwind 主题 + `styles/` + next-themes；重做 `ui/` 基础组件（card/button/input）与三栏布局的质感。
- **不改交互逻辑**，纯视觉层。
- **留给设计团队**：整体风格基调（候选方向：现代科技感 / 卡牌收集感 / 简洁专业，三选或自拟）。

### 模块 B — 结构化协作（任务看板）
- **目标**：让协作从"松散群聊"变成"有流程、可追踪"。
- **设想**：
  - 将 `tasks-view` 升级为 **Kanban 看板**：`待办 / 进行中 / 待审 / 完成` 四列。
  - **chat ↔ task 联动**：群聊里 `@委派` 某角色 → 自动生成一张任务卡；卡片状态随该 agent 工作流转（`pending → running → done`），在看板与消息流中双向可见、可点击互跳。
  - 中栏增加 `[💬 线程] / [📋 看板]` 视图切换。
- **涉及组件**：增强 `tasks/tasks-view.tsx`；在 `chat/chat-message.tsx` 识别"委派类消息"并挂载任务卡。
- **留给设计团队**：看板与群聊的空间关系（切换 / 并列分栏 / 抽屉）。

### 模块 C — 角色卡片系统（核心）
- **目标**：不同角色有不同卡片；对话过程中可挑选并"加入"角色。
- **设想**：
  1. **角色卡片库**：每个角色一张卡——头像 / 名字 / 专业领域 / 能力标签 / 模型徽标。角色数据可对接现成角色模板库（如 VoltAgent 的 ~160 个专业角色：PM、前后端、安全审计、设计、各语言专家…）。
  2. **"+ 角色"入口**：在 `chat-input` 旁加按钮（类比"加附件"），点开**角色卡片库**（网格，可搜索 / 按分类筛选）。
  3. **对话中加入**：选中一张角色卡 → 加入当前群聊 → 消息流中插入一条"XX 已加入"的角色卡片 → 此后该角色发言均带其卡片化身份（头像 + 名牌）。
  4. **左栏"角色墙"**：用角色卡片展示当前在线的团队成员（替换/增强现有 agent 列表）。
- **涉及组件**：复用并增强 `agents/agent-status-card.tsx` 与 `agent-avatar.tsx`；`chat-input` 加入口；`chat-messages` 新增"角色卡片"消息类型。
- **留给设计团队**：
  - 卡片形态——**建议富卡**（技能标签 + 可展开能力清单 + 模型/成本徽标，强化"组队卡牌"感），也可做紧凑卡。
  - 卡片库的浏览 / 筛选 / 搜索体验。
  - "加入"动画与消息流中卡片的视觉。

## 4. 关键用户流程

1. **进入** → 左栏看到团队"角色墙"，中栏可切线程/看板，右栏群聊。
2. **临时加专家** → 点 `[+ 角色]` → 浏览卡片库 → 选"安全审计师" → 一条"已加入"卡片插入对话 → 该角色立即参与讨论。
3. **派活追踪** → 群聊 `@委派` → 看板生成任务卡 → 随 agent 状态流转 → 完成归档。

## 5. 范围与优先级

- **P0（先做）**：A 视觉升级 + B 任务看板。
- **P0/ 核心**：C 角色卡片系统（不同角色不同卡片 + 对话中加入）。
- **后续可选**：角色库对接更多外部模板、跨模型徽标、token/成本可视化、角色"技能"开关。

## 6. 开放设计决策（待团队拍板）

1. 整体视觉风格基调。
2. 角色卡片形态：富卡 vs 紧凑卡。
3. 看板与群聊的布局关系。
4. 角色卡片库的浏览交互。
5. "加入角色"的动效与反馈。

## 附：技术约束与提示

- 基于 OpenAgents fork，`docker-compose` 本地自部署（workspace 后端 + 前端），agent 连本地 workspace。
- 前端：Next.js 16（App Router）+ React 19 + Tailwind 4 + Radix UI + lucide-react + next-themes。
- "加入角色"后台对接 launcher（`agn create --type claude --path <角色目录> + connect`）拉起真实 agent；角色的"人格/方法论"由该角色目录下的 `CLAUDE.md` 注入（已验证可行）。
- 角色可跨模型：claude 角色复用 Claude Code 登录免 API key；openclaw 角色走本地 MiniMax 等。
